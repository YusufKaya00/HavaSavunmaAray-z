## 2024-05-03 - C# Shared Memory Optimizations
**Learning:** In C# applications reading uncompressed video frames (1.2MB each) at high frequencies (~60fps) from shared memory via `MemoryMappedFile`, instantiating large `byte[]` buffers and `CreateViewAccessor()` instances inside the processing loop causes severe Garbage Collection (GC) pressure and Large Object Heap (LOH) fragmentation.
**Action:** Always pre-allocate large byte arrays and `MemoryMappedViewAccessor` objects outside the `while (true)` loops and reuse them across iterations to maintain performance.
## 2024-07-01 - WinForms Message Queue Flooding
**Learning:** In C# WinForms applications processing high-frequency data (like 60fps video frames from shared memory), using asynchronous `BeginInvoke` without flow control can flood the WinForms message queue faster than the UI can render. This leads to massive memory bloat (as closures and images queue up) and eventually an `OutOfMemoryException` or locked UI.
**Action:** Always implement a flow control mechanism (like a `volatile bool isUpdatingUI` flag) when passing high-frequency data to the UI thread via `BeginInvoke`. Drop frames in the background loop if the UI thread is still processing the previous frame.
