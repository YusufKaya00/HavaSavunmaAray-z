## 2024-06-25 - LOH Fragmentation in High-Frequency C# Shared Memory Reads
**Learning:** Instantiating large byte arrays (~1.2MB for 640x640x3 frames) and `MemoryMappedViewAccessor` objects inside a high-frequency (e.g., 60 FPS) `while(true)` loop causes extreme Large Object Heap (LOH) fragmentation. Because these objects exceed 85,000 bytes, they go straight to the LOH. The garbage collector struggles to keep up with frequent LOH allocations, leading to severe GC pauses, increased memory footprint, and frame drops in real-time applications.
**Action:** Always pre-allocate large buffers and reusable stream/accessor objects *outside* of high-frequency execution loops. Reuse these pre-allocated instances within the loop (e.g., passing the same `byte[]` to `accessor.ReadArray(...)`) to achieve zero-allocation per frame and maintain consistent performance.
